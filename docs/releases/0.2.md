# Release 0.2

## Features

- Seven-day program rotation. Today's plan is derived from the date instead of hardcoded.
- Morning check-in: sleep, body, energy, and whether you played yesterday.
- Adaptive days. Low readiness forces recovery, consecutive court days downshift to mobility, and middling readiness downshifts anything demanding. The header shows what was scheduled and why it changed.
- Seven-day history strip with logged-day count and average completion.
- Export and restore the full history as JSON.
- Supplements and evening routine items are completable and count toward the day.
- Explicit "day complete" state.
- Light and dark themes that follow the system.

## Fixes

- The greeting and date were rendered during a static prerender, baking the build date into the HTML and mismatching on hydration. Both now resolve after mount and refresh at noon, 5pm, midnight, and on foreground.
- The storage key was computed once at mount, so a PWA left open overnight wrote today's data under yesterday's key.
- The storage key used a hardcoded `America/Los_Angeles` timezone while the header used the device timezone. All dates are now the local calendar day.
- "Next action" fell back to the last checklist item once everything was done, so a finished day still showed an outstanding action.
- Completion percentage ignored supplements and the evening routine, and treated hydration and protein as all-or-nothing. Scoring now covers every card on screen and gives partial credit.
- Dark mode was declared in CSS but broken, because components hardcoded hex values past the tokens. Every colour is now a semantic token.
- Completable rows exposed no state to assistive technology. They are buttons with `aria-pressed`; progress bars use `role="progressbar"`; steppers announce their value.
- Notes wrote to local storage on every keystroke. Writes are debounced and flushed on hide, unmount, and day change.
- Day records were never pruned and never read back.
- The service worker cache name was a frozen literal, so returning users could hold stale assets forever. `cacheFirst` could reject and surface as a hard network error.
- `/_next/static/` was excluded from caching, so offline never actually worked.
- No `apple-touch-icon` existed, so installing on iPhone produced a generic icon.

## Decisions

- ADR-0004: the day plan is derived from the date and adapted by readiness.
- ADR-0005: semantic design tokens; components never hardcode colour.
- ADR-0002 amended: local storage is not durable, so export and restore ship as a product feature.

## Migration

Records written by 0.1 (`court-ready-dashboard-v1:<date>`) are converted to `court-ready:v2:day:<date>` on first load and the originals removed. The migration is idempotent and never overwrites an existing record.

## Testing

- 76 unit tests across `lib/date.ts`, `lib/resolve-day.ts`, `lib/progress.ts`, and `lib/storage.ts`.
- Verified in a browser: render, adaptation, persistence across reload, 0.1 migration, complete-day state, and both themes.

## Known Issues

- The React component layer has no automated tests.
- `vitest` is pinned to v3; v4 requires a newer Node than this project currently runs.
- The service worker cache version is bumped by hand.
- Editing the plan means editing `lib/program.ts`.
