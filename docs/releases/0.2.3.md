# Release 0.2.3

Hardens the export path. Shipped on a misdiagnosis; kept because the resulting
behaviour is better, but the premise below was wrong and is corrected here.

## What actually happened

A report from the installed iOS app — "export doesn't do anything but try to
export a json" — was read as "Export is dead". It was in fact a question about
whether exporting a JSON file was the intended behaviour. It was.

The assumed cause, that WebKit rejects `application/json` through the Web Share
API and forced a fall-through to a silently-dropped `<a download>`, **did not
occur on the device in question**. Confirmed afterwards: the share sheet appears
and offers a `.json` file, so `canShare({ files: [jsonFile] })` returns true and
the first strategy succeeds. The fallback ladder never runs there.

Treat the "WebKit rejects JSON" claim as unverified. It is a real restriction in
some WebKit versions, but it was not this bug, and no evidence was gathered for
this device or iOS version.

## Why the change was kept

The fallback ladder is now defensive rather than load-bearing, but two parts of
this release fix genuine defects independent of the misdiagnosis:

- A cancelled share sheet previously recorded a successful backup, so backing
  out of the sheet marked the user as backed up when nothing had been saved.
- Export could claim "Backup downloaded" on a platform where the download had
  been dropped. It can no longer report success it did not achieve.

## Changes

- **A share plan instead of a single guess.** `lib/share.ts` probes progressively plainer shapes and picks the first the platform accepts: a `.json` file, then the same bytes as a `text/plain` `.txt` file, then the raw JSON as share text. All probing goes through `canShare`, which is synchronous and does not consume the user gesture, so exactly one real `share()` call still happens inside the click.
- **Export can no longer be a no-op.** On an installed app where nothing is shareable, the backup goes to the clipboard and the status says so, instead of pretending a download occurred.
- **Honest status messages.** Sharing as text is reported differently from sharing a file, and a cancelled share sheet stays silent and does not record a backup.
- **Restore accepts `.txt`**, since the share path may hand iOS a text file.

## Testing

- 97 unit tests, up from 89. `lib/share.test.ts` covers each rung of the fallback ladder, that the payload survives every strategy, and that planning only probes and never shares.
- Browser-verified against five simulated platforms: the exact reported failure (standalone, JSON rejected), standalone with no share support at all, standalone with JSON accepted, a cancelled share sheet, and a desktop browser.

**Verified on device afterwards:** the share sheet appears and offers a `.json`
file. The `.txt` and clipboard rungs remain untested against real iOS, because
nothing on that device triggers them.

## Lesson

An ambiguous bug report was treated as a confirmed diagnosis, and a fix shipped
before the failure was reproduced. Ask what the user actually saw before
building the remedy.
